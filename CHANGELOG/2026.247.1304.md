# 2026.247.1304 — feat: root-capable postgresql (crabbox loop-cutover exit 1)

## Summary

Root-capable PostgreSQL — named-batch **exit 1** of `plan/crabbox-loop-cutover.md`
(distro-cachyos). Root-posture boxes (uid 0, the nesting-recipe path that makes
crabbox's lease hostname settable) previously failed postgres `initdb
("cannot be run as root")`, crash-looping the coordinator. The entrypoint now:

- detects uid-0, prepares the DECLARED `PGDATA`/`SOCKET_DIR` (the `~/.postgresql`
  volume path stays stable for every box user), chowns them to the distro's
  `postgres` OS user (created by the postgresql package), and re-execs the whole
  body via `runuser -u postgres -- $0`;
- uid-1000 boxes (immich/jupyter/openclaw/…) take the identical path as before
  (the branch is skipped when not root).

Also migrates the root schema to 2026.240.1943 and bumps the candy version
(2026.247.0100) for the functional change. Adds the in-tree
`postgresql-not-root` runtime check (B12): asserts the server process user is
never root — it fails without the root-capable branch on a root-posture box
and passes identically on uid-1000 boxes.
